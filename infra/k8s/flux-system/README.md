# 🌀 Flux CD (GitOps) Setup for drive-ops Production

This directory contains the GitOps engine configuration for our **Production** environment using Flux. Flux automatically synchronizes the state of the local Kubernetes cluster with the manifests located in the `infra/k8s/prod-flux` directory.

## 🛠 Prerequisites
* A running Kubernetes cluster.
* The `kubectl` CLI installed.
* The `flux` CLI installed (`curl -s https://fluxcd.io/install.sh | sudo bash`).
* A GitHub Personal Access Token (Classic) with `repo` permissions.

## 🚀 Step 1: Bootstrap Flux (Installation)
Unlike traditional manifests, Flux is installed and connected to the repository via the CLI. It generates its own manifests and commits them directly to this repository.

1. Export your GitHub token:
   ```bash
   export GITHUB_TOKEN="ghp_your_token_here"
   ```

2. Run the bootstrap command (configured for token authentication to bypass organization SSH key restrictions):
   ```bash
   flux bootstrap github \
  --owner=UA-4697-DevOps \
  --repository=drive-ops \
  --branch=main \
  --path=infra/k8s/flux-system \
  --personal=false \
  --token-auth
   ```

## 📂 Step 2: Architecture & Application Sync

* `flux-system/`: Contains the GitOps Toolkit components (auto-generated by the bootstrap command).
* `apps-sync.yaml`: A custom `Kustomization` resource that tells Flux to watch the `infra/k8s/prod-flux/` directory and deploy our production microservices.

## 🧪 Step 3: Verify Automated Synchronization (Self-Healing Test)

To verify that Flux is actively protecting the Production environment:

1.  Check for the presence of the production test config:
    ```bash
    kubectl get configmap gitops-test-prod
    ```
2. Simulate a failure by manually deleting it:
   ```bash
   kubectl delete configmap gitops-test-prod
   ```
3. Immediately check again (or force reconciliation):
   ```bash
   flux reconcile kustomization apps-sync --with-source
kubectl get configmap gitops-test-prod
   ```
Flux ensures the cluster strictly matches the Git source of truth!

## 📊 Step 4: Monitoring Flux

Since Flux is CLI-first and headless by default, use these commands to monitor its status:

* Watch synchronization status in real-time:
  ```bash
  flux get kustomizations -w
  ```
* View system health:
  ```bash
  flux check
  ```
